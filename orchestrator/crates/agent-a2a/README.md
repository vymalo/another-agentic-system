# orch-agent-a2a

`AgentClient` over the A2A protocol (`a2a-client-lf`): live card and
release-channels discovery, streaming delegation, resubscribe, polling and
cancel.

## Where it sits

An **adapter** of the `AgentClient` port in [`orch-ports`](../ports/README.md).
An agent is an A2A agent-card URL and nothing else: no agent host, gateway or
host SDK is a dependency
([ADR 0007](../../../docs/decisions/0007-protocol-only-dependencies.md)).
Host conveniences are an optional extension, read live from the card, never
cached and failing closed
([ADR 0008](../../../docs/decisions/0008-platform-integration-via-a2a-extension.md)).
The release-channels extension itself is specified in the
`vymalo/another-agentic-platform` repository
(`docs/extensions/release-channels-v1.md` there).
Only the binary ([`orchestrator`](../../bin/orchestrator/README.md)) depends on it.
The pure mapping from A2A values to envelopes and idempotency keys lives in
[`orch-a2a-mapping`](../a2a-mapping/README.md); this crate is the client around it
(HTTP, streaming, resubscribe, errors, release channels, the thread-tools grant). It depends on
[`orch-thread-token`](../thread-token/README.md) to mint the token; nothing else of the orchestrator's surfaces.

## API at a glance

| Item | What |
|---|---|
| `A2aAgentClient::new(A2aConfig) -> Result<_, BuildError>` | implements `AgentClient`; installs the `rustls` crypto provider if none is installed |
| `A2aConfig` | `card_timeout` (5 s), `connect_timeout` (10 s), `read_timeout` (90 s), `call_timeout`, `use_system_proxy`, `thread_tools` (the issuer of the thread-tools grants, `None` by default), `fetch_files` (a `FileFetch`: `None` by default) |
| `releases_from_card(&AgentCard) -> Option<Releases>`, `RELEASE_CHANNELS_URI` | reads the optional release-channels extension from the live card (the URI is defined in [`orch-a2a-mapping`](../a2a-mapping/README.md) and re-exported) |
| `ui_from_card(&AgentCard) -> Option<UiSupport>` | reads the optional A2UI extension ([ADR 0013](../../../docs/decisions/0013-a2ui-generative-ui.md)) from the live card: an `extensions` entry whose `uri` is exactly `https://a2ui.org/a2a-extension/a2ui/v0.9.1` or `…/v1.0` (both detected, open question 22; `v0.9.1` preferred when both are listed). Anything else is not A2UI |
| `build_from_card(&AgentCard) -> BTreeMap<String, String>` | the scalar parameters of the first extension of the card whose URI has a path segment `build`, as text; empty for a card with none (never an error). What the dispatcher notes as the agent's build ([ADR 0053](../../../docs/decisions/0053-a-thread-export-says-which-builds-made-it.md)); that adam-rs lists such an extension is unverified |
| `extensions_from_card(&AgentCard) -> BTreeSet<KnownExtension>` | which extensions of the orchestrator's own (`ui-catalog/v1`, `thread-tools/v1`, `steps/v1`, `mentions/v1`: `orch_core::KnownExtension`) the live card lists, by exact URI (a near miss is not listed); `read_card` returns them in `AgentCardInfo.extensions` |
| `A2aConfig.thread_tools: Option<Arc<ThreadToolsIssuer>>`, `thread_tools_metadata(&ThreadToolsGrant, &[AttachedServer]) -> Value` | what mints the `thread-tools/v1` grants (the keys, the URL agents reach the orchestrator at and the token lifetime, from [`orch-thread-token`](../thread-token/README.md); `None` by default, so no agent is given a grant) and the value of the extension's key in the message metadata, `{url, token, expiresAt}` and, when servers are attached, `attached` |
| `A2aConfig.asks: bool` | whether the thread endpoint the grants open offers `ask_agent` (ADR 0026); **off** by default, so a message that mentions agents carries no `coordinate` member. The binary turns it on whenever it mints grants (`A2aConfig.thread_tools`), in every role, because the endpoint the grants open mounts `ask_agent`; the end-to-end world does the same |
| `steps_from_card(&AgentCard) -> bool` | whether the live card lists `steps/v1` by exact URI ([ADR 0025](../../../docs/decisions/0025-nested-steps-events-carry-their-source-path.md), [`steps-v1.md`](../../../docs/api/steps-v1.md)) |
| `SendRequest.steer` | **`steer/v1`** ([`docs/api/steer-v1.md`](../../../docs/api/steer-v1.md), [ADR 0036](../../../docs/decisions/0036-sending-while-an-agent-works.md)): a message for a running task. The adapter sends it only when the card read for this very call lists `steer/v1` by exact URI (otherwise `AgentError::Unsupported`, nothing is sent: fail closed), activates the extension in the `A2A-Extensions` header and in `message.extensions`, and sends it with the task's `taskId` and the thread's context, no references, no release, no catalog, no A2UI capabilities and none of the reporting extensions (`steps/v1`, `text-stream/v1`); the thread-tools grant rides along as on any message, and so does the `mentions/v1` metadata of the message when the same card also lists that extension (`SendRequest.mentions`). The first event of the stream is the agent's answer; the dispatcher reads it and drops the stream. `tests/steer.rs` runs it against the in-process agent (the `steerable` script) |
| `text_stream_from_card(&AgentCard) -> bool` | whether the live card lists `text-stream/v1` by exact URI ([ADR 0027](../../../docs/decisions/0027-live-text-relayed-not-stored.md), [`text-stream-v1.md`](../../../docs/api/text-stream-v1.md)): the extension is activated, with `steps/v1` and on the same two calls, on `SendStreamingMessage` (the header and `message.extensions`) **and on `SubscribeToTask`** (the card is read for it too), so an agent sends its reply as chunks as it writes it; the response is read as data whether or not it was activated, so a chunk is a live piece (`AgentEnvelope.live`, never applied) and the text the agent states is one `agent_message` under the stream's id (`orch_a2a_mapping`) |
| `usage_from_card(&AgentCard) -> bool` | whether the live card lists `usage/v1` by exact URI ([ADR 0056](../../../docs/decisions/0056-token-usage-per-model-call.md), [`usage-v1.md`](../../../docs/api/usage-v1.md)): the extension is activated with `steps/v1` and `text-stream/v1`, on `SendStreamingMessage` (the header and `message.extensions`) and on `SubscribeToTask`, so the agent reports each model call's tokens and its task's totals (`orch_a2a_mapping`). A stream shows no task metadata: when a stream that activated it reaches a status that ends or pauses the task **without** the totals in the update, the adapter reads the task once (`GetTask`, within `call_timeout`) and passes its totals on before the status; a read that fails passes nothing (a debug line). An agent whose card does not list it is never asked and its task is never read for them |
| `client_capabilities(UiVersion, Option<&UiDelivery>, accepts_inline)`, `inline_catalog`, `ui_catalog_metadata(&UiDelivery, inline)`, `action_part(&UiActionData, Timestamp)` | the renderer capabilities a message carries (`a2uiClientCapabilities` `{"v0.9.1": {supportedCatalogIds, inlineCatalogs?}}`, or `a2uiRendererCapabilities` `{"v1.0": …}`; with a UI catalog the screen's own id is listed **first** in `supportedCatalogIds` and the catalog is in `inlineCatalogs` only when `inline_catalog` says so), the `ui-catalog/v1` metadata (`{catalogId, version, digest, inline}`), and the `application/a2ui+json` data part that carries a user's action back (`[{"version", "action": {name, surfaceId, sourceComponentId, timestamp, context}}]`) |
| `install_crypto_provider()` | idempotent `rustls` provider setup |

`ui_from_card` also reads whether the entry of the version spoken says `acceptsInlineCatalogs: true` (`UiSupport.accepts_inline_catalogs`; only a boolean `true` counts).

**Steps** ([ADR 0025](../../../docs/decisions/0025-nested-steps-events-carry-their-source-path.md)): an agent whose live card lists `steps/v1` is asked for steps: the URI is activated in `A2A-Extensions` **and** in `message.extensions` on `SendStreamingMessage`, and in `A2A-Extensions` on `SubscribeToTask` (a resubscribe reads the card too, which it did not before). A card without the exact URI is asked for nothing, and the card is read for every call, never remembered. What the agent reports is read by [`orch-a2a-mapping`](../a2a-mapping/README.md) as data whether or not the request asked. `tests/steps.rs` runs the activation (the header, the message's `extensions`, no activation for a card without it or with a near miss, the card read for every message, a resubscribe asking again, none when the card dropped it) and the steps of the fake agent arriving nested, and the same chatty step arriving as often as the agent says it (coalescing is the core's).

**The UI catalog** ([ADR 0023](../../../docs/decisions/0023-ui-component-catalog-as-an-a2a-extension.md)): `SendRequest.ui_catalog` (the delivery the core decided: the catalog inline, or a reference to the current one) is sent **only to an agent whose live card lists `ui-catalog/v1`**. The message then carries `metadata["https://agents.vymalo.com/a2a/extensions/ui-catalog/v1"] = {catalogId, version, digest, inline}` on every message, our catalog id first in the A2UI `supportedCatalogIds`, and the catalog itself in `inlineCatalogs` when it is an inline delivery **and** the A2UI entry of the card says `acceptsInlineCatalogs: true` (otherwise `inline: false` and the agent asks for the catalog again); the URI is activated in `A2A-Extensions` and `message.extensions`. A card without the URI gets exactly the message it got before. *Verified 2026-10-01* (the end-to-end test `two_screens_of_different_versions_reach_the_agent_as_the_extension_says`): a receiver built on `a2a-server-lf` reads every number of the message's metadata as a double (`maxLength: 256` arrives as `256.0`, `version: 2` as `2.0`), so an agent that recomputes the digest of an inline catalog must write a whole number as an integer first (RFC 8785 does). 

**Files** ([ADR 0032](../../../docs/decisions/0032-files-from-agents-live-in-an-artifact-store.md)): a `raw` part of an artifact arrives as `AgentUpdate::File` (the mapper). A `url` part stays the artifact's link, unless `A2aConfig.fetch_files` (`FileFetch { hosts, max_bytes, timeout }`, from `artifacts.fetchHosts` and `artifacts.maxFileBytes`) lists its host: the adapter then reads it and sends `AgentUpdate::File` as if the agent had sent the bytes (the type is the part's own, else the server's `Content-Type`; the file name is the last path segment), on a stream, a resubscribe, a poll and a cancel alike. The list is the SSRF control, and a host on it is trusted. A URL is read only when it is `http` or `https` with no credentials and its host and port (the scheme's default when the entry has none) are an entry; no redirect is followed (it would leave the list), nothing of the agent or the thread is sent, the body is read piece by piece and stopped at the cap (`FileRefusal::TooLarge`; also on a `Content-Length` over it), and the whole request has a time limit (30 s). A fetch that fails (a status, a redirect, a connection, a time-out) is `AgentUpdate::FileRefused { reason: NotKept }`, logged with the host only. An artifact that has text as well as a link is left a link.

**Attached servers** ([ADR 0024](../../../docs/decisions/0024-mcp-tools-attached-per-conversation.md)): `SendRequest.thread_tools` (a `ToolsGrant`) also carries `attached`, the MCP servers attached to the thread that the agent may use (id, name, description: the dispatcher reads the thread's set when it sends and keeps those the deployment offers for the agent). `thread_tools_metadata(&ThreadToolsGrant, &[AttachedServer])` writes them as `attached: [{server, name, description?}]` beside `{url, token, expiresAt}`, **only** in a message that carries the grant (so only for a card that lists `thread-tools/v1`, an adapter with keys and a request with a grant), and leaves the member out when there are none; it carries no URL, header or credential. `tests/thread_tools.rs` pins it: the member and its shape, the endpoint's the only URL, none attached no member, and a card without the extension, an adapter without keys told nothing.

**The mentions of a message** ([`mentions/v1`](../../../docs/api/mentions-v1.md), [ADR 0026](../../../docs/decisions/0026-agent-mentions-as-structured-references.md)): `SendRequest.mentions` (the `MentionInfo`s the dispatcher resolved from the registry when it sent: id, name, label, offsets, card URL) becomes `metadata[<mentions/v1 URI>] = {mentions: [{agentId, name?, label, start, end, cardUrl?}], coordinate?}` and the URI is activated in `A2A-Extensions` and `message.extensions`, **only** when the card read for this very call lists `mentions/v1` (exact URI), the content is text and the message mentions someone; any other agent is sent the text as it is, labels in it, and nothing else. The text is never rewritten, so the offsets index it as the agent receives it, except for the first task of a fork, whose agent is told the conversation in front of the text: they move by that preamble's length in UTF-16 code units. `coordinate` (`{"tool": "ask_agent"}`) needs the card to list `thread-tools/v1` too, a grant minted for the message, and `A2aConfig.asks`. A mention the dispatcher could not resolve goes with id, label and offsets only. `tests/mentions.rs` pins it against the fake agent over HTTP: a card that lists it is told (and activated), every other card (none, `thread-tools` only, `mentions/v2`, a trailing slash) is not, a message that mentions nobody carries nothing, `coordinate` needs all of its conditions, a fork's offsets move; the unit tests in `src/mentions.rs` pin the shapes.
**The thread tools** ([`thread-tools/v1`]**The thread tools** ([`thread-tools/v1`](../../../docs/api/thread-tools-v1.md), [ADR 0023](../../../docs/decisions/0023-ui-component-catalog-as-an-a2a-extension.md)): `SendRequest.thread_tools` (the non-secret grant the dispatcher builds: the thread, the job, the agent, `main`, depth 0; `None` for the verifier) becomes `{url, token, expiresAt}` under the extension's URI in the message metadata, and the URI is activated in `A2A-Extensions` and `message.extensions`, **only** when the card read for this very call lists `thread-tools/v1` (exact URI), the request has a grant and `A2aConfig.thread_tools` has an issuer. The token is minted when the message is sent (one per message, `jti` is the message id, wall-clock `iat`), from the issuer's keys; a grant that cannot be minted is logged without a secret and leaves the agent without tools, never failing the message. Nothing else sees the token: it is not in the request (which holds only the grant), the outbox, the log, or a log line (`ThreadToolsGrant` and the issuer print no secret, and nothing here logs the metadata); a test captures every log line of a send at the most verbose level and finds neither the token, a segment of it, nor the key. A card without the URI, an adapter without keys and a request without a grant get exactly the message they got before.

**A fork's conversation** ([ADR 0029](../../../docs/decisions/0029-forking-a-thread-copies-its-log.md)): the first task of a fork has no task to continue (a fork is a context of its own), so `SendRequest.history`, when set, is put in front of the text of a `SendContent::Text` as `orch_core::history_preamble` (a record, fenced, not instructions), in the **same** text part: plain A2A, any agent reads it. Nothing is sent for a UI action (a data part), for an empty history, or when `history` is `None`, which is every later task of the fork, every message of a thread that is not a fork and the verifier's.

**The context is the agent's** ([ADR 0055](../../../docs/decisions/0055-the-agent-assigns-the-a2a-context.md)): `SendRequest.context_id` is `None` for the first message of a conversation and the message then names no `contextId` (an agent such as kagent refuses one it did not create, and the protocol has the agent make it); the agent's answer names the context in every envelope, the dispatcher records it, and later messages carry it. `find_task_by_message(ep, None, id)` lists the tasks of every context (the same page limit). `tests/contexts.rs` runs the adapter against an agent that refuses a context it did not create (`FakeAgentOptions::strict_contexts`) and one that echoes.

A selected release is sent as the `A2A-Extensions` header plus namespaced
message metadata; `SendRequest.reference_task_ids` becomes the message's `referenceTaskIds` ([ADR 0021](../../../docs/decisions/0021-context-across-a2a-tasks.md)). **A2UI is sent only when the card read for that very call lists it** (capabilities in the
metadata, the URI in the header and in `message.extensions`); a card that lost it makes the next message plain
A2A again. A surface from an agent is relayed whether or not its card lists the extension, and an action goes
back in the version its surface spoke (ADR 0013). Methods used: `SendStreamingMessage`, `SubscribeToTask`
(the port's `resubscribe`), `GetTask`, `CancelTask`, `ListTasks`.
`SubscribeToTask` only works while the task executes in the answering
process; otherwise `TASK_NOT_FOUND`, which the dispatcher answers by polling
`GetTask`. The SDK loses the HTTP status of failed calls, so errors are
classified by JSON-RPC code and by the SDK's message prefixes.

```rust
use orch_agent_a2a::{A2aAgentClient, A2aConfig};

let agents = A2aAgentClient::new(A2aConfig::default())?;   // then PortSet { agents, .. }
```

Protocol notes above are as recorded in `src/lib.rs`: *verified* against the
SDK sources on 2026-09-29 by that crate's author; not re-checked for this
README.

## Features and environment

No Cargo features. The crate reads no environment variables; bearer tokens
arrive in the endpoint's `AgentTransport::A2a { card_url, bearer }` (the binary
resolves `tokenEnv` from `AGENTS_FILE`); the adapter serves that transport only.
An `AgentTransport::Local` endpoint (an agent hosted in-process) is answered with
`AgentError::Unsupported` by every operation, never dereferenced as a card URL.
