# orch-agui-projection

The AG-UI view of the event log, as pure functions: a fold from orchestrator events to AG-UI
frames, and the translation of a `RunAgentInput` to core inputs. No `async`, no I/O, so the
compiler enforces that the projection stays a function of the log.

The normative mapping is [`docs/api/agui.md`](../../../docs/api/agui.md)
([ADR 0012](../../../docs/decisions/0012-ag-ui-user-facing-protocol.md)): the event log is the only
source of truth ([ADR 0001](../../../docs/decisions/0001-rust-state-machine-on-postgres.md)) and AG-UI
is a view of it. Protocols are closed enums
([ADR 0004](../../../docs/decisions/0004-closed-enums-over-dyn-registry.md)), so the frames are the
typed events of [`orch-agui-proto`](../agui-proto/README.md).

## Where it sits

Depends on [`orch-core`](../core/README.md) (the events and inputs) and
[`orch-agui-proto`](../agui-proto/README.md) (the wire types), and on nothing else of the
orchestrator: no `orch-app`, no store, no HTTP. The AG-UI surface ([`orch-surface-agui`](../surface-agui/README.md)) is the adapter that feeds it events from `App::event_stream` and writes its frames as SSE.

## API at a glance

| `Connect::new(ThreadMeta, cursor, head, Follow)`, `feed(&Event) -> Vec<Frame>`, `caught_up()` (the log is folded up to `head` and the frames are being written: when live text may be handed to the overlay), `finished()` | the connect stream as a fold: the events up to the cursor are folded and not written, the preamble comes at the cursor, every later event is written; `Follow::ThroughRun` (`?mode=run`) is `finished()` once the log as it stood at `head` is replayed and no run is open. | `agent_step` (ADR 0025, ADR 0030) | a step of the agent's work ([`agui.md`](../../../docs/api/agui.md#nested-steps), [`steps-v1.md`](../../../docs/api/steps-v1.md)): a **sub-agent step is a subagent** (`SUBAGENT_STARTED{sub-step-<seq>, parentSubagentRunId}`) nested under the subagent that encloses it, and every step is a `vymalo.step` activity (`step-<seq>`, said again with `replace: true` at every event of the step, attributed to the enclosing subagent, `startedAt` and `at`). The `vymalo.step` content carries `input`, `output` and `ioDropped` as logged ([ADR 0030](../../../docs/decisions/0030-a-step-carries-its-input-and-output-bounded-and-redacted.md)): the input of the start is said again by every later snapshot of the step, the output is on the end's |

A pending `error` still explains the `thread_state` that follows |

```rust
use orch_agui_projection::{Audience, Connect, Follow, Projector, ThreadMeta};

let mut projector = Projector::new(meta);
for event in log {
    for frame in projector.apply(&event, Audience::Viewer) {
        // write `frame.event` as one SSE `data:` line, and `id: <seq>` when `frame.resume_id` is set
    }
}
// A client reconnects with Last-Event-ID = c: fold the events up to c, discard their frames,
// send `resume_preamble()`, then keep applying the events after c. `Connect` is that, packaged:
let mut connect = Connect::new(meta, cursor, head, Follow::Forever);
for event in log {
    for frame in connect.feed(&event) { /* write it */ }
    if connect.finished() { break; } // only with Follow::ThroughRun
}
```

## Rules the fold keeps

- **A function of the events.** The state never depends on the frames emitted or on the
  audience, so every replica agrees and a reconnect can rebuild it by folding up to the cursor.
- **Runs are balanced.** A run opens at the first event of a burst of activity (a user message, or
  an event nobody asked for) and closes at the event that ends it; nothing a run opened (a text
  message, a subagent invocation) is open when it ends. Between the core's transactions a run is
  open exactly when the thread is `queued`, `working` or `verifying`. The module docs of `src/projector.rs`
  explain how a run closes, including the two cases the log cannot tell apart.
- **Ids come from the log.** `run-<seq>`, `sub-<seq>`, `int-<seq>`, `evt-<seq>`, or the ids a
  surface recorded (`user_message.data.messageId` / `runId`).
- **Resume points** are the sequence numbers of whole log events, and never fall inside a text
  message of the log. A live message is not in the log: it holds no resume point back and has none.

None, and no environment variables.

## Tests

Offline, no database. `cargo test -p orch-agui-projection`:

- `tests/projection.rs`: every row of the outbound table on a hand-written log (asking and
  answering, `auth_required`, failure, cancel, delivery failures, late and repeated events, partial
  messages, audiences, the resume preamble, the view); the agent's words as a text triad (and
  not twice, never for `failed`, after an open partial), `at` on every activity, the kind and
  fields of each artifact, and a kept file (ADR 0032: its `href`, `sha256`, `size`, `filename` and `preview` for an
  image, a text, an attachment-only type and an SVG, and a file that was not kept saying none of them); and ADR 0031: `vymalo.purpose` and `vymalo.via` on a message's `START`
  when the event has them (and no member when it has not, for an unmarked message and for the
  status words), also when a connection joins while a message is open; and the log the core writes after an
  announced answer (the answer `via: turn_output`, the closing line as a `working` message, the status that keeps it): two
  assistant messages and no `st-<seq>` (the projection is unchanged: the core says the status words, so they are found said).
- `tests/send.rs`: a message while the agent works on the logs the core writes (`Action::StopAndSend` is in the generator): a steer and a stop frame by frame, `vymalo.delivery`, every end of a stopped task, no verification for the abandoned job under a gate (and again when the stop is refused for good), a task that asks while it is stopped, two stops, a message while the work is verified, the requester not getting its message back, and a reconnect at, before and after the message (preamble, then exactly the rest). `tests/translate.rs` has the `vymalo.send` rows, `tests/live.rs` the live draft that ends abandoned with the run.

The log generator of the properties (`tests/support/log.rs`) has `Ask`, `AskEnd` and `AskStep` actions, so every property (well formed at every prefix, resume from any point, nothing open at a terminal event, a function of the log) holds with asks in the log.
- `tests/tools.rs`: attached servers on hand-written logs: the snapshot and the card inside a run (one resume point, on the card), a detach and the empty set (no `tools` member), a run of its own on a finished thread and the close on a cancelled or failed one, the creation commit's attach inside the run its message opened, a new job keeping the set, a viewer that resumes after the change told the set by the preamble and not the card again, and no URL in any frame. `tests/golden.rs` adds `tools-attach` to the scenarios.
- `tests/fork.rs`: a fork on hand-written logs- `tests/fork.rs`: a fork on hand-written logs: the marker run frame by frame, `forkedFrom` in every snapshot from the marker on and in none before it, the next message starting job *n+1* (also after a fork of job 2), a run the copy left open closed as cancelled, a copied question not an interrupt of the fork (`resume` ignored with a warning), the copy's cards not actionable, the copy's ids known, the UI catalog forgotten. `tests/props.rs` has a `Fork` action in its random logs (the log so far becomes a fork of itself at a cut `fork_cut` allows).
- `tests/description.rs`: a description row by row, as the title's (inside a run: one `STATE_SNAPSHOT` with `thread.description` and a resume point; of a finished, cancelled or waiting thread: a run of its own with the snapshot and the close the state gives; every later snapshot says it; a person clearing it is a snapshot with none; the last writer standing; no frame but the snapshot; not a resume point while a message is open) and a fork that has its parent's description from its marker on.
- `tests/title.rs`: a rename row by row (inside a run: one `STATE_SNAPSHOT` with the new title and a resume point; of a finished, cancelled, failed or waiting thread: a run of its own with the snapshot and the close the state gives, the interrupt and the failure said again, not new ones; no frame but the snapshot; not a resume point while a message is open).
- `tests/ci.rs`: a CI report as a `vymalo.ci` card (content, id `ci-<sha>-<name>`, `replace`), its place before the check it decided, a re-run replacing its card and another commit having its own, a report nobody counts still a card and changing nothing, a report after the job ended opening and closing a run of its own, ids that do not depend on what was folded before, hostile text carried as text and only `http(s)` links passed on, every conclusion's `passed`. The property tests' logs include CI reports too.
- `tests/props.rs` (proptest over logs made by the core's own `transition`, with and without a gate, and with messages that carry UI catalogs): the stream is well
  formed at every prefix (against a Rust model of the reference consumer's rules in
  `tests/support/verify.rs`, and the vendored schema through `orch_agui_proto::testkit`); nothing
  is open at a terminal event; resuming from any resume point gives exactly the suffix, and the
  preamble plus the suffix is a well-formed stream; the requester differs from the viewer only in
  the messages it holds.
- `tests/connect.rs`: `Connect` over the same random logs. From every cursor the stream is the preamble of
  the state at the cursor followed by the frames of every later event, which is what an uninterrupted
  stream wrote after that `id:` (the frames a client held plus the reconnect are the stream once); the
  result is well formed; `?mode=run` writes what the default writes and ends at the first idle point at
  or after the end of the log as it stood at connect time, for every head and cursor; the edges by hand
  (a cursor beyond the head, the preamble at the cursor before the next event, an idle thread, a gap).
- `tests/capabilities.rs`: the document with and without release channels, with each A2UI extension URI and both, and for an unreadable card,
  validated against the schema.
- `tests/a2ui.rs`: surfaces and actions on hand-written logs: whole-surface snapshots under one message id, two surfaces in one payload, delete and recreate, the replay cap, foreign operations skipped, a late surface, an action's run and activity, resuming from a cursor. `tests/props.rs` and `tests/connect.rs` include surfaces, refused parts and actions in their random logs.
- `tests/translate.rs`: every row of the inbound table, and that re-sending the whole transcript
  never duplicates input; the A2UI action rows (the surface the thread has and its version, unknown or deleted surface, malformed, oversized, ambiguous, the rules of any input).
- `tests/live.rs`: each rule of the overlay on hand-written logs (opening at offset 0, UTF-16 offsets and UTF-8 placement, overlap, repeat, gap and refresh, joining mid-stream, the last piece, giving up, a second stream opening, a late piece, another agent's piece, a piece inside a character, the size bound, pieces held before the invocation and dropped with the run, the final continuing the live message, a final that replaces it, an abandoned id said again, resume points kept while a live message is open, the message ended before its invocation, a question and the run; the `END` of a live message the log marked working text says so and an answer's does not; and that the projector's own resume points are untouched), then proptest over random interleavings of pieces (overlaps, repeats, gaps, refreshes, late and foreign pieces, giving up, replies the log never says) and log events: every prefix is well formed, each reply the log says reads as its text, the resume points are the projection's own, and a new overlay started at any resume point writes a well-formed stream that reads every later reply as its text.
- `tests/golden.rs`: [`docs/api/examples/agui/*.agui.json`](../../../docs/api/examples/README.md) are
  produced from the `*.events.json` goldens (and `stream.feed.json`, a log with live text in the order a
  connection heard it, through the overlay); every frame conforms to the schema and the streams are
  well formed. `UPDATE_GOLDEN=1 cargo test -p orch-agui-projection --test golden` rewrites them.
  `tools/agui-conformance` feeds the same files through the reference client in CI. The fork goldens
  (`fork`, `fork-blocked`) carry a second thread id, the one the fork was cut from, as `<parent-thread-id>`.
- `tests/sharing.rs` (ADR 0040): a share and an unshare say nothing outside a run, nor inside one, which goes on; an `error` before a share still explains the state that follows.
