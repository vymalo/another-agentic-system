# orch-api

The HTTP edge of the orchestrator: an axum 0.8 router whose identity layer asks the `Authenticator` port,
RFC 9457 problems, the resource API (agents, thread list and details, export, cancel)
and health, over `orch_app::App`. Interaction surfaces plug into it, and
`health_router` serves health alone.

## Where it sits

The always-mounted part of the HTTP interface between the chat UI and the
orchestrator. It depends on [`orch-app`](../app/README.md),
[`orch-ports`](../ports/README.md) (generic over `Ports`) and
[`orch-core`](../core/README.md); it names no adapter and no surface. The
interaction routes live in surface crates that depend on this one
([`orch-surface-agui`](../surface-agui/README.md)); the
binary ([`orchestrator`](../../bin/orchestrator/README.md)) mounts the ones
`ORCH_SURFACES` names
([ADR 0012](../../../docs/decisions/0012-ag-ui-user-facing-protocol.md)).

The interaction routes come from a
surface (`/agui/*`, from `orch-surface-agui`). Bodies are limited to 1 MiB; request ids are set and
propagated. The four legacy interaction operations (`createThread`, `postMessage`, `listEvents`,
`streamEvents`) were removed on 2026-09-30 (ADR 0012): `POST /api/threads` answers 405 (its path
is served for `GET`) and the other three paths 404, with or without a surface mounted.
`GET /api/agents` is read from the agent registry on every request ([ADR 0022](../../../docs/decisions/0022-platform-provisions-agents-system-discovers-them.md)): the static agents and the registry's, each with `source` and `tags`.
```rust
let app: std::sync::Arc<orch_app::App<_>> = /* built by the composition root */;
let cfg = orch_api::ApiConfig::default();
let agui = orch_surface_agui::routes(app.clone(), cfg.sse_keepalive);
let router = orch_api::router_with_surfaces(app, cfg, vec![agui]);
// axum::serve(listener, router).await
```

Identity is what `app.ports().auth()` makes of the request's credentials: the token of `Authorization: Bearer`
(another scheme is not a bearer; a header that is empty, sent twice or not text is a bearer that is refused) and
`X-Auth-Request-Email` (one that is not text is read as empty). Every path except `/healthz`, `/readyz` and
`/metrics` is refused unless it authenticates, surfaces' paths and unknown ones included, and a credential that
is present and bad is refused even when another would have served.

| Outcome | Response |
|---|---|
| authenticated | the `Principal` (the user, and the roles of the credential) is in the request extensions: a handler takes `Extension<Principal>` and hands it to the application, which enforces the roles ([ADR 0033](../../../docs/decisions/0033-the-orchestrator-is-an-oauth2-resource-server.md)); there is no bare `UserId` extension any more |
| authenticated, and the roles grant nothing | 403 problem with `code: no_access`, from every route but `GET /api/me`: a valid token with no role the configuration defines and no `auth.defaultRole` |
| `Missing`, `Invalid` | 401 problem; with `WWW-Authenticate: Bearer realm="orchestrator"` when the authenticator reads bearer tokens, and `, error="invalid_token"` when a token was presented and refused (RFC 6750); when it also reads DPoP (`accepts_dpop()`, `auth.dpop`) a second header `DPoP algs="ES256 EdDSA"`. A refused **proof** is `WWW-Authenticate: DPoP error="invalid_dpop_proof", algs="ES256 EdDSA"` alone, and a token that is bad as a DPoP one, not bound to the proof's key, or **bound and sent as a bearer**, `DPoP error="invalid_token", algs="ES256 EdDSA"` (RFC 9449 §7.1) |
| `Unavailable` (the issuer's keys cannot be fetched), `NotConfigured` | 503 problem with `Retry-After: 5`: nobody is let in, and it is not a refusal of the caller |

`/readyz` is 503 (`not ready: cannot authenticate`) while the authenticator's `ready()` fails, so a pod whose issuer's keys were
never fetched is kept out of the service. `/healthz` does not follow it.
**The identity header is only trustworthy behind a proxy (oauth2-proxy) that strips client-supplied copies**; with
`auth.mode: jwt` it is not read at all.

### Roles and permissions

What a person may do is the application's ([`orch-app`](../app/README.md#api-at-a-glance), `authz`): the handlers pass the
`Principal` and map the answer. `AppError::NotFound` is the 404 `no such thread` (a thread the person may not read is the
answer for one that does not exist), `AppError::Forbidden` is a 403 whose `code` is `forbidden` (a permission or an agent
the roles lack); there is no `read_only` code since ADR 0039, because nobody reads a thread that is not theirs.

* **`GET /api/me`** (`getMe`): `{user, email?, name?, roles, permissions: [{permission, scope?}], agents: {read, invoke}, sharing?, maxTier?}` (`maxTier`: the highest access tier the person may pick for a message, [ADR 0061](../../../docs/decisions/0061-the-person-picks-an-access-tier-for-each-message-the-agent-keeps-to-it.md): the highest `maxTier` of their roles that hold `agent.invoke`, absent when any of those has none, as the built-in `user` and `admin` do; a hint for the screen, since the application decides per agent each time it writes a message), `Cache-Control:
  no-store`. It answers a person whose roles grant nothing too, so that a client can say why every other route is a 403. Never a check: the
  orchestrator enforces every request.
* **`GET /api/threads`**: the caller's own threads, newest first, and nobody else's. An `owner` parameter (the administrators' way to list another person's
  or everyone's threads until [ADR 0039](../../../docs/decisions/0039-nobody-reads-another-persons-thread.md)) is a 400, `owner is not supported (ADR 0039)`, with any value.
* **`Thread.owner`**: every serialised thread says its owner (the e-mail), which is always the caller's own.
* **Streams**: `sse::stream_budget(&principal, now)` is how long a stream may stay open for a credential (its `exp` plus 60 s, at most an hour,
  `None` for one that does not run out) and `sse::bounded(stream, budget)` ends a stream when it is spent; the AG-UI surface applies them to its
  connect and run streams, and the client resumes with `Last-Event-ID` and a fresh token.
* Tests: `tests/rbac.rs` drives it all over HTTP from bearer tokens (`MemoryAuth`) and checks the answers against `docs/api/chat-api.yaml`; it pins `maxTier` of `GET /api/me` (the highest cap of the roles that let the person invoke, absent when any of those has none, and a role that cannot invoke has no say) and the `tier` of a fork body (a word that is not a tier, a tier without a text, a tier above the cap, a tier at or below it, none from a capped role is its cap, for an edit too). `problem.rs` pins that a card that cannot be read is a 503 "the card of the agent <id> could not be read" with `Retry-After: 5` (class `Transient`, but not the store's text).

### `GET /api/threads/{id}/export`

The thread as one downloadable JSON document, for the owner to send to a developer
([`docs/orchestrator.md`](../../../docs/orchestrator.md#exporting-a-thread), operation `exportThread` of the contract).
Authorised exactly like `GET /api/threads/{id}`: behind the identity layer (401 without it), and `App::export_thread` reads the
thread as the caller (`thread.read`), so a thread the caller may not read, an unknown one and an id that is not a UUID are the same 404. The answer is
`200 application/json` with `Content-Disposition: attachment; filename="thread-<id>.json"` and `Cache-Control: no-store`,
pretty-printed: `{format, version: 1, exportedAt, thread, job, binding, events, eventsTruncated, versions}`. `thread` is the contract `Thread`; `job` is the
whole ledger (which `Thread.job` only summarises), with its `number` (which job of the thread this is, [ADR 0020](../../../docs/decisions/0020-a-thread-is-a-conversation.md)); `events` is the log in order from `seq` 1 exactly as stored, and stops at
`thread.lastSeq`, or earlier when a bound of the read cuts it (`eventsTruncated`; the head is kept, with no gap). No credential of the orchestrator is in a log (the bearer token of an agent is held by
`AgentTransport::A2a` only); the file does hold what people and agents wrote, and the owner's e-mail as the actor of their
messages. `versions` says which builds made it ([ADR 0053](../../../docs/decisions/0053-a-thread-export-says-which-builds-made-it.md); no member is ever absent, and what is not known says `unknown`): `orchestrator` `{version, revision}` (the crate version, and the commit from the build argument `ORCH_BUILD_REVISION`, `ORCHESTRATOR_REVISION`), `agents` (every agent that worked in the thread, from the binding, the actors of the log and the asks, each with the entries of `job.builds`: the card's `name`, `version`, build parameters and `fromJob`, as the dispatcher read them when it gave the agent work, or one entry `{name: null, version: "unknown"}`) and `web` `{revision}` (the request's `X-Web-Revision` when it is 1 to 64 characters of letters, digits and `._+-`, else `unknown`; `web_revision`). Built in `src/export.rs`; unit-free (a `Serialize` struct that borrows the `ThreadExport` the application returns and is written straight to the body, with no `serde_json::Value` copy of the log).

### `GET /api/threads/{threadId}/artifacts/{sha256}`

A file an agent handed over, from the artifact store ([ADR 0032](../../../docs/decisions/0032-files-from-agents-live-in-an-artifact-store.md),
operation `getArtifact`). Behind the identity layer; `App::open_artifact` decides who may read (the permission `artifact.read` of ADR 0033 over the thread:
the owner's and nobody else's, an administrator's included; a role without it is a 403), and **every miss is the same 404**:
a thread that is not the caller's, a thread that does not exist, a hash the thread holds no file for (the file of another thread is not reachable by
hash), a hash that is not 64 lowercase hex digits, and a deployment with no artifact store. `src/artifacts.rs` says how the file is sent:

* **streamed** from the store, never held whole (an inline SVG is the one exception, read to be sanitized, up to `MAX_SVG_INLINE_BYTES`, 2 MiB);
  a store that fails midway ends the response in an error so that a prefix is never taken for the file, and nothing of the error is sent;
* **inline** (no `download`, or `download=0`) only for `orch_core::Preview` types (png, jpeg, gif, webp, svg, `text/plain` and `application/json`, the
  last two with `; charset=utf-8`); every other type is an `attachment`, and so is every `?download=1`, with the original bytes;
* every type that is not a preview type is sent as **`application/octet-stream`**, whatever it was kept as: the web allows scripts and styles of its
  own origin, and a kept `text/javascript` or `text/css` loaded by a `<script>` or `<link>` of an injected page would run there (with `nosniff` a
  browser runs or applies nothing of another type);
* a request whose **`Sec-Fetch-Dest`** is `script`, `worker`, `sharedworker`, `serviceworker`, `style` or `object` is a **403** before the file is
  opened (on the owner's route and both shared ones); a request without the header goes on;
* an inline **SVG is the sanitized one** (`orch-svg-clean`); one that is too large or cannot be sanitized is sent as an attachment instead;
* **a redirect** (`deliver`, [ADR 0058](../../../docs/decisions/0058-large-files-go-up-through-a-presigned-url-the-orchestrator-gives-the-agent.md) A1, `artifacts.s3.downloads: redirect`, off by default): with a store that can presign, the same three routes (the owner's and both shared ones) answer **`302`** to a presigned `GET` instead of the bytes, after every check above, unchanged and first (a refusal is never a redirect; a file the store no longer holds is the same 404), without reading the file (one `HEAD` for its type, size and name). `Location` is the URL, `Cache-Control: private, no-store` (`no-store` on a link route, whose hardening sets it on everything), `Referrer-Policy: no-referrer` (it governs the request the browser is sent on, per the Fetch and Referrer Policy specifications as read on 2026-10-14, not tried in a browser; the page that asked may be a share link's `/s/<token>`), and no body. The URL signs `response-content-disposition` (`inline` only for a preview type without `?download=1`, else `attachment`, with the same cleaned name), `response-content-type` (the kept type for a preview type, `application/octet-stream` for every other) and `response-cache-control` (`private, max-age=<the URL's life>`), all decided by one pure function (`redirect_overrides`) from the rules above (`content_type`, `disposition_header`); it lives `artifacts.s3.presignTtlSecs` and at most 60 seconds through a link. **An SVG shown inline is never redirected** (sanitized and streamed as above), and that means one up to `MAX_SVG_INLINE_BYTES` (2 MiB), the most that is read to be cleaned: with `?download=1`, or when it is larger than that, it is redirected as the attachment the streamed route would send it as (the size is the `HEAD`'s, so the file is read by nobody here). The headers of the signature are built as text (`disposition_text`, which `disposition_header` makes a header value of), and a value a header cannot carry is a 500, never a stream. A `HEAD` or a signing that fails is a 5xx (`503` with `Retry-After`, or `500` for a deployment whose store says it signs and does not), **never the bytes by another road**; `X-Content-Type-Options`, the `Content-Security-Policy` and the CORS headers are the files host's, not the route's;
* always `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; sandbox`
  (`ARTIFACT_CONTENT_SECURITY_POLICY`), `Cache-Control: private, max-age=31536000, immutable` (`ARTIFACT_CACHE_CONTROL`) and `ETag: "<sha256>"`;
* `Content-Disposition` carries the file name cleaned (one name, no path, no control or direction character, 255 bytes), as a printable ASCII
  `filename="…"` fallback (`"`, `\`, `%` and `;` replaced) and, when the name is not that, `filename*=UTF-8''…` (RFC 6266, RFC 5987); no usable name is
  `artifact-<8 hex digits>`; a `download` that is not `0`, `1`, `true` or `false` is a 400.

### Shared threads

([ADR 0040](../../../docs/decisions/0040-thread-sharing-by-revocable-link.md), [`chat-api.yaml`](../../../docs/api/chat-api.yaml).)

| Route | Answer |
|---|---|
| `PUT /api/threads/{id}/share` `{ visibility }` | the owner (with `thread.share`) shares: `200` with the link (the token is in the body of this answer and of a rotation, and nowhere else, `Cache-Control: no-store`); refused when `sharing.mode` is `disabled` or the level is above the cap; the same request again changes nothing |
| `POST /api/threads/{id}/share/rotate` | a new link; the old one stops working at once |
| `DELETE /api/threads/{id}/share` | takes the link down; **needs only ownership**, not `thread.share` |
| `GET /api/shared/{token}`, `GET /api/shared/{token}/artifacts/{sha256}` | signed in (`thread.read`, `artifact.read`): the reader's projection (`SharedThread`; a signed-in reader is told `agentName`, the display name of its agent) and a file the log names |
| `GET /api/public/shared/{token}`, `GET /api/public/shared/{token}/artifacts/{sha256}` | no identity (an `Authorization` header is ignored): the same for a `public` thread; a file only with `sharing.public.files` |

Every link that does not work is the same `404` with the same body (an unknown token, a bad MAC, a private or revoked thread, a lowered
cap, a file that is not the thread's, an `internal` thread on the public route). Every answer about a shared thread is `Cache-Control:
no-store` and `X-Robots-Tag: noindex, nofollow` (a stream adds `no-transform`); a shared file is never cached. A thread's own `GET` and
listing carry `share` for its owner only. The public layer is `guard`: with no limiter (the composition did not build one) every public
request is that 404, so public sharing fails closed; `ApiConfig::check` refuses a composition with the cap `public` and no limiter (the binary always builds one and maps the refusal to exit 78). The request span holds the
path with the token cut, and `tests/span.rs` pins that no log line of a request holds a token.


### DPoP and `GET /api/public/auth` (ADR 0054)

The identity layer reads `Authorization: DPoP <token>` beside `Bearer` and hands the authenticator a `DpopCredentials`: the token, every
`DPoP` header (a header that is not text is `""`), the request's method and its path **as received** (the `OriginalUri` when a router
nested it, else the URI). It reads no proof itself and never reads `DPoP` without the `DPoP` scheme; two `Authorization` headers are one
refused bearer, as before. Whether a deployment takes DPoP, which origins it is called at and what a proof must say is the authenticator's
([`orch-auth-jwt`](../auth-jwt/README.md)). A stream opened by a DPoP request is bounded by the token's `exp` through the same
`Principal::expires_at` (`sse::stream_budget`) as a bearer's.

`GET /api/public/auth` answers `{"issuer", "clientId", "scope"}` (camel-cased, `Cache-Control: no-store`) from `ApiConfig.browser_auth`, and the
one 404 of a route that does not exist when there is none. It is mounted with the public routes: **outside the identity layer** (no credential is
read, even a bad one beside it is ignored), behind the same rate limiter (a 404 of this route is no guess at a link, so it does not charge the
shared bucket the failure surcharge, since a deployment without browser sign-in is asked once by every page), and with no limiter, as for every public
route, it is the 404.

### People's own MCP servers ([ADR 0046](../../../docs/decisions/0046-people-add-their-own-mcp-servers-secrets-in-a-credential-broker.md), slice 4b)

`src/user_tools.rs` and the listing in `src/routes.rs`. The routes are mounted always and are a **404 while the feature is off**
(`userToolServers.enabled`; a layer asks `App::user_tool_servers_enabled` before the body is read). Every handler calls one method of
`App` (which holds the permission and owner checks) and none is given a port. **`POST`, `PATCH` and `DELETE` run that call in a task of
their own** (`to_the_end`) and wait for it, as the broker does for a refresh (ADR 0046, departure 27): axum drops a handler's future when
the client hangs up and the 30 s `request_timeout` drops it too, and a drop between two writes would skip the compensation after them. A
request that is dropped still finishes its sequence and its answer goes nowhere. A task that panicked, or that the runtime ended, is a 500
with the fixed `internal error`.

| Route | Does | Answers |
|---|---|---|
| `POST /api/user-tool-servers` | `{name, url, auth, secret?}`: adds one (`tools.user.add`). `auth` is `{kind: none \| bearer \| api_key \| oauth2, header?, scopes?, clientId?}`, **the same object a response writes**; `secret` is the token or the key, required for `bearer` and `api_key` | 201 with the server; 400 for a value that cannot be used and, `code: url_refused`, for a URL the egress guard refuses (the guard's **public** reason in `detail`, never the rule or an address); 403 `forbidden`; 404; 409 `too_many_servers` (the ninth); 422 `credentials_not_kept` (a kind that wants a credential in a deployment that keeps none); 503 `broker_down` + `Retry-After` (the broker could not keep the secret: the definition is taken back, nothing is left unless that fails too); 500 (the write panicked or was ended; read the list) |
| `GET /api/user-tool-servers` | the person's own, sorted by name, each with `url`, `auth`, `state`, `status`, `reason?`, `hasCredential`, `revision`; `limit` (8) and `kinds`; needs no permission of its own | 200 `{servers, limit, kinds, error?}`; a definition that does not read back is a **200 with no servers and `error: {code: unreadable}`** (the other servers are not lost and each can be deleted by its id; the answer cannot name the damaged one, so its `detail` sends the person to the operator, who finds the id in the orchestrator's log, one warning per damaged row, written by the store); 404; 503 |
| `PATCH /api/user-tool-servers/{id}` | any of `name`, `url`, `auth`, `secret` (re-keys), `revision` (`tools.user.add`) | 200 with the server; as `POST`, and 404 for an id that is not the caller's, 409 `stale_revision` |
| `DELETE /api/user-tool-servers/{id}` | deletes one and forgets its credential (revoke, then delete); **no permission needed** | 204; 404 (also the second time, another person's, a malformed id); 503 `broker_down` (the credential could not be revoked: the server stays) |
| `POST /api/user-tool-servers/{id}/authorize` | starts the OAuth authorization of an `oauth2` server (`tools.user.add`); **no request body** (one is not read) | 200 `{authorizeUrl, issuer, expiresAt}` (`Cache-Control: no-store`: the URL carries the `state`, which is not a member of its own); 404 for a server that is not the caller's or not `oauth2`, 422 `credentials_not_kept` / `oauth_not_configured` / `egress_refused` (the guard's one public sentence), 429 `rate_limited` (`Retry-After`), 503 `authorization_unavailable` (`Retry-After`) |

* **The secret is write-only.** `SecretBody` reads these bodies itself: `ApiJson` answers with serde's messages, and serde quotes a string it finds
  where it expected a map (`invalid type: string "…"`), which here can be the secret. Every refusal is a fixed sentence that names no value and
  no member the sender chose; the secret becomes a `ToolSecret` by moving the string; no response, error, log line or event carries it
  (`tests/user_tools_secret.rs` plants sentinels and searches the responses, the log at `TRACE` with the spans, the thread log, the definitions
  and every `Debug`; a canary shows that the capture would find one). The request logging records the method and the path, never a body. The
  buffer the body arrived in, and the JSON value a string passed through, are not wiped.
* **The URL is the person's own** and shown back to them (so they can edit it); it can hold a secret in its path, so these answers are
  `Cache-Control: no-store` and nothing logs a URL.
* **The revision** is a string in the listing; send it back as `revision` of a `PATCH` and a server that changed since is 409. It is a body
  member, not `If-Match`: the listing has no per-server `ETag`, and a header outside the CORS allow-list would break the desktop and mobile apps
  (ADR 0047).
* **`GET /api/tool-servers`** (the picker) has the deployment's servers exactly as before and then the person's own with `own`, `status` and
  `reason`. With the feature off it is byte for byte what it was. A definition that does not read back, or a store of definitions that is down, leaves
  the person's servers out of it and the deployment's stay (the picker is how those are attached too; a warning in the log says why, with no
  person and no server in it; `GET /api/user-tool-servers` keeps its 503 for a store that is down). `status` asks the broker for nothing (`App::list_own_tool_servers`).

### Authorizing an OAuth server: the rate limit, the callback and the document ([ADR 0046](../../../docs/decisions/0046-people-add-their-own-mcp-servers-secrets-in-a-credential-broker.md), slice 4c)

`src/authorize_limit.rs` and `src/oauth.rs`; `authorize` is in `src/user_tools.rs`, behind the same layer that makes the routes a 404 while the feature is off.

* **`authorize` is limited per person**, by `AuthorizeLimiter` (`ApiConfig.authorize_limits`, `AuthorizeLimits { burst: 10, refill: 6 s }` by default: **ten a minute**). A call makes the broker fetch URLs that a stranger's metadata names, so
  the limiter is in front of everything else and **every call counts**, a refused one too. The bucket is in memory, **per process** (with several replicas a person gets that many times as many), keyed by the
  person; the table is bounded (`MAX_PEOPLE` = 4096: a person with a full bucket is forgotten, and a person it has not met is refused while the table is full of persons who are not idle). A call refused is a **429** with
  `Retry-After` (whole seconds, at least 1) and `code: rate_limited`. Time is `tokio::time::Instant`, so a test with paused time moves it.
* **The callback**, `GET /api/user-tool-servers/oauth/callback`, is **outside the identity layer** (the browser that comes back carries no session: [ADR 0047](../../../docs/decisions/0047-one-ui-for-web-desktop-and-mobile-each-signs-in-as-a-public-oauth-client.md)),
  mounted with the public routes but with its own guard (`callback_guard`): the rate limiter of the public routes under a key of its own (`oauth-callback`; the document has `oauth-client-metadata`, so a flood of one cannot limit the other; all public routes draw on one bucket), no limiter means unlimited and not a 404, a 404 problem while the feature is off,
  the request timeout. **A limited request is the fixed page** (429, `Retry-After`, the same headers; the link is not spent, since the handler was not reached), and **the timeout layer's bare 503** on this route is the page "could not be finished" with the same headers (`page_for_a_timeout`, a `map_response` outside the timeout; the work runs on in its task). It reads `code`, `state`, `iss` and `error` from the query and nothing else (`error_description` is never read; an unknown name is ignored, as RFC 6749 asks); **a known parameter given twice, or a query over 16 KiB, is an invalid
  link and spends nothing**. It runs `App::finish_user_tool_authorization` **in a task of its own**, so a browser that closes the connection cannot leave it between the broker keeping the grant and the definition naming it. `HEAD` is a
  **405** (`Allow: GET`): axum would run the `GET` handler for it and a prefetch would spend the `state`. The answer is an HTML page of **fixed text** (200 "You can return to the app", 400 "This link is not valid", 400 "The authorization was not completed",
  503 "could not be finished"), with nothing of the request on it, and `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` (so the page has no script and no style), `Referrer-Policy: no-referrer`,
  `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` and `X-Robots-Tag: noindex, nofollow`.
  **The query is never logged**: `trace::redact_uri` writes `…` for it on this path.
* **The Client ID Metadata Document**, `ClientMetadata::new(client_id_url, client_name, redirect_uri)`, `ApiConfig.client_metadata`: served at the path of the client identifier (`GET`, outside sign-in, behind the same guard,
  `Cache-Control: public, max-age=300`, and under the limiter key `oauth-client-metadata`). It says `client_id` (the URL byte for byte), `client_name`, `redirect_uris` (the callback alone), `grant_types`, `response_types` and `token_endpoint_auth_method: none`. `new` refuses a URL that is not `https`
  with a host and a path, and a path under `RESERVED_PATHS` (`/api`, `/agui`, `/mcp`, `/thread-tools`, `/webhooks`, `/healthz`, `/readyz`, `/metrics`, `/oauth2` (the orchestrator and oauth2-proxy), `/edge-healthz`, `/.well-known` (the edge), `/config.json`, `/s`, `/auth`, `/signed-in`, `/threads`, `/_next`, `/_not-found`, `/brand`, `/404.html`, `/index.html`, `/favicon.ico`, `/icon.svg`, `/apple-icon.png`, `/manifest.webmanifest` (the web): also exported as `CLIENT_METADATA_RESERVED_PATHS`; the binary's test holds the list
  equal to the configuration's), and a redirect URI whose path is not `OAUTH_CALLBACK_PATH` (`ClientMetadataError::RedirectPath`: the document would list a redirect that ends at a 404). `OAUTH_CALLBACK_PATH` is the path of the callback.

### `GET /metrics`

The outbox queue as Prometheus text (`text/plain; version=0.0.4`), written by hand (four
samples; no metrics crate), read from the store on every scrape through
`App::outbox_stats`. A store failure is 503. The values are global (every replica's rows), so
any process can answer.

| Sample | Meaning |
|---|---|
| `orch_outbox_rows{state="due"}` | rows a worker could claim now: `pending` and due, or `inflight` with a lapsed lease |
| `orch_outbox_rows{state="waiting"}` | rows `pending` in retry backoff |
| `orch_outbox_rows{state="leased"}` | rows `inflight` under a live lease: a worker is on them |
| `orch_outbox_oldest_due_age_seconds` | whole seconds since the oldest due row became due, `0` when none |
| `threads_deleted_total` | counter: threads deleted by this process, the edits of a deleted thread included ([ADR 0043](../../../docs/decisions/0043-deleting-a-thread-erases-it.md)) |
| `late_input_dropped_total{source="dispatcher"\|"inbox"}` | counter: results and rows a worker held for a thread that was deleted meanwhile, dropped and never retried |
| `usage_reports_dropped_total{reason="invalid"\|"job_limit"}` | counter: token usage reports this process did not log ([ADR 0056](../../../docs/decisions/0056-token-usage-per-model-call.md)): `invalid`, they broke the `usage/v1` contract; `job_limit`, a valid call report past the job's 10 000. Names no thread and no agent |
| `history_pages_total`, `history_events_folded_total`, `history_fold_seconds_total` | counters: pages of thread history answered by this process, the log events folded for them, and the seconds spent reading and folding ([ADR 0059](../../../docs/decisions/0059-a-thread-opens-at-its-end-and-older-turns-load-on-scroll-up.md), `App::history_stats`); the mean cost of a page is the second over the first. They name no thread and no person |
| `access_tier_echoes_dropped_total` | counter: access tier echoes this process did not log ([ADR 0061](../../../docs/decisions/0061-the-person-picks-an-access-tier-for-each-message-the-agent-keeps-to-it.md)): an agent said a tier that was not one of the four words; the echo is dropped and the task goes on |
| `thread_purges_pending` | gauge: threads deleted whose files are still to be erased, over every replica's rows (`App::purges_pending`; left out when the store cannot say). It is `0` when the inline purge worked; a value that stays up says the artifact store is down or the sweep is not running |

The pure `render(&OutboxStats, now)` is unit tested against a golden text. How to scale
workers on it: [`docs/orchestrator.md`](../../../docs/orchestrator.md#observability-and-scaling).
